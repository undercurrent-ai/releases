BreachRadar

Breach monitoring and an outreach queue, on your own machine

Watches SEC EDGAR 8-K Item 1.05 filings and six incident-press feeds, and puts every new disclosure in front of you as a triage queue rather than a dashboard you have to remember to open.

Eight columns from Inbox to Call booked. The day counter on each card is computed as it renders, so a target sitting in Hold turns colour by itself on the morning it enters the window you care about. Nothing is auto-filed into an outbound column — extracting an organisation from a headline is a heuristic and it is wrong often enough to matter.

No daemon, no API keys, no telemetry and no server. It polls when you open it, or once a day at most. Your board, notes and settings stay in a folder in your home directory and an update never touches them.

Breach Radar 0.3.2

A packaging fix. If you already have 0.3.1 running, nothing about the app changes — but 0.3.1 could not be installed by anyone who downloaded it, so it should not be passed on.

Downloads open properly again. The 0.3.1 bundle was signed before the database CLI was copied into it, which invalidates the signature. That is invisible on the machine that built the app — a local build carries no quarantine flag, so macOS never checks — and fatal everywhere else: a downloaded copy reports *"BreachRadar is damaged and can't be opened"*, which right-click → Open cannot get past. The CLI is now copied in before signing, and the build refuses to continue if the signature does not verify, so this cannot ship again without someone noticing.

Downloading Breach Radar for the first time still shows the usual *"unidentified developer"* prompt, because the app is signed ad-hoc rather than with an Apple Developer ID. Right-click the app and choose Open to get past that one; it is asked once, per machine.

Everything in 0.3.1 — per-contact claim codes, server-chosen subdomains, and the move of your board to ~/.undercurrent/db/breachradar/ — is unchanged and described in NOTES-0.3.1.md.

First launch. These builds are ad-hoc signed, so macOS asks once. The one-time steps are here — later updates are installed by the app itself and never hit that prompt.
